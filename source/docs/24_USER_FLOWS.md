# 사용자 흐름

## 가입 신청

1. 임직원이 `/groupware/signup`에서 필수 항목을 입력한다.
2. 클라이언트 검증 후 Supabase Auth 사용자를 만들고 DB 트리거가 `pending` 프로필을 생성한다.
3. 계정 상태는 `pending`이며 내부 페이지 접근을 허용하지 않는다.
4. 사용자는 승인 대기 화면에서 처리 원칙과 문의처를 확인한다.
5. 관리자가 승인 또는 거절하고 모든 조치를 감사 로그에 남긴다.

역할·최종 부서·직급·직책은 신청 메타데이터가 아니라 관리자가 확정한 DB 값만 권한 판정에 사용한다.

## 로그인과 보호 경로

1. 사용자가 로그인 정보를 제출한다.
2. Supabase Auth 세션과 DB 프로필·역할을 확인한다.
3. `approved` 계정만 원래 요청 경로로 이동한다.
4. 비로그인, 승인 대기, 거절, 잠금, 비활성 계정은 내부 데이터를 받지 않는다.

`pending`, `rejected`, `locked`, `resigned`는 상태 안내로 이동하며 UI 메뉴 숨김과 별개로 RLS와 RPC가 권한을 다시 검증한다.

## 비밀번호 재설정

1. 사용자가 회사 이메일을 입력한다.
2. Supabase가 재설정 메일을 발송한다.
3. Supabase의 일회성 재설정 흐름을 사용한다.
4. 완료와 실패는 계정 존재 여부를 과도하게 노출하지 않는 문구로 안내한다.

## 관리자 승인

1. 관리자가 대기 신청 목록을 조회한다.
2. 조직, 직급·직책과 기본 역할을 확인한다.
3. 승인 또는 거절 사유를 입력한다.
4. 승인·거절 RPC가 호출자의 관리자 역할을 재검증한 뒤 상태를 변경하고 감사 로그를 기록한다.
5. 승인된 사용자만 다음 로그인부터 내부 경로를 사용할 수 있다.

상세 상태는 [`27_AUTH_AND_MEMBERSHIP.md`](27_AUTH_AND_MEMBERSHIP.md), 권한은 [`28_ROLE_AND_PERMISSION_MATRIX.md`](28_ROLE_AND_PERMISSION_MATRIX.md)를 따른다.

## App Shell 모바일 흐름

1. 메뉴 버튼이 Drawer를 열고 첫 메뉴로 포커스를 이동한다.
2. `Escape`, X, 오버레이 또는 메뉴 선택으로 Drawer를 닫는다.
3. 닫힌 후 메뉴 버튼으로 포커스를 복귀한다.
4. 1024px 이상으로 전환되면 Drawer 상태를 정리하고 고정 Sidebar를 표시한다.
