# 관리자 시스템

## 관리 영역

- 회원 승인·거절과 대기 목록
- 계정 잠금·해제, 비활성화와 보관
- 부서·직급·직책과 구성원 배정·이동
- 역할·권한 관리
- 게시판 생성·설정·보관
- 팝업 문서 HTML/일반 편집, 노출 위치와 게시 기간 관리
- 전자결재 분류·양식·입력 필드·기본 결재선과 버전 발행
- 시스템 설정
- 감사 로그와 로그인 기록

## 부서 수명주기

부서 삭제 요청은 다음 순서를 강제한다.

1. 비활성화
2. 소속 직원 이동
3. 게시판·결재·일정·파일·감사 이력 사용 여부 확인
4. 이력이 있으면 보관
5. 이력이 없는 경우에만 최종 삭제 검토

최종 삭제는 서버 함수, 재인증, 사유 입력과 감사 로그가 필요하다.

## 회원 승인

- 신청 정보와 회사 이메일을 확인한다.
- 승인 시 부서, 직급·직책과 최소 역할을 명시한다.
- 거절·잠금·해제·퇴사 처리에는 사유를 기록한다.
- 관리자 자신에 대한 고위험 권한 변경과 마지막 최고 관리자 제거를 방지한다.

## 감사 기준

- 대상, 작업, 이전·이후 값의 안전한 요약, 사유, 작업자와 시각을 기록한다.
- 비밀번호, 토큰과 민감한 본문은 감사 로그에 남기지 않는다.
- 감사 로그 조회 권한과 보유 기간은 `[미정]`이다.

## G2 화면

- pending 회원 목록과 신청 상세를 조회한다.
- 관리자가 최종 부서·직급·직책과 대표 역할을 선택하고 RPC로 승인한다.
- 거절 사유를 필수로 받아 RPC로 거절하며 결과를 즉시 목록에 반영한다.
- 부서·직급·직책은 생성, 이름·코드·순서 수정과 활성·비활성만 제공하고 삭제는 제공하지 않는다.
- 일반 관리자의 관리자 계열 역할 부여는 서버 함수에서 거부한다.

## 첫 최고 관리자

자동 승격은 금지한다. 정상 가입 후 `supabase/snippets/bootstrap_super_admin.sql`의 이메일 placeholder를 SQL Editor에서 일회성으로 바꿔 실행하며 승인·역할 부여·감사 로그를 한 트랜잭션에서 기록한다. 이 절차는 Data API나 브라우저 RPC로 노출하지 않는다.

## G3 구성 화면

- 대시보드 위젯: 유형·문구·이동 경로·크기·정렬·활성·필수·사용자 숨김/정렬 허용·보관과 역할/조직/사용자별 allow·deny 배포를 관리한다.
- 게시판 빌더: 그룹, 10개 유형, Sidebar·댓글·대댓글·첨부·익명·반응·검색 설정, 카테고리, 게시판 관리자와 action별 권한 규칙을 관리한다.
- 위험한 전체 관리 권한은 저장 전 별도 확인하며, 특정 사용자 기준 권한 미리보기로 서버 판정 결과를 확인한다.
- 사용 이력이 있는 위젯·게시판의 안전 삭제 요청은 보관으로 전환하고, 사용 이력이 없을 때만 물리 삭제한다.

## 팝업 문서 관리

- `/groupware/admin/popups`에서 HTML 또는 일반 편집기로 안내 문서를 작성한다.
- 그룹웨어 세부 화면과 공개 사이트 메인·개인정보처리방침 또는 각 영역 전체를 노출 위치로 선택한다.
- 게시 시작·종료 시각, 활성·보관과 정렬 순서를 서버에서 검증한다.
- 공개 화면에는 현재 게시 기간인 활성 문서만 RPC로 전달하며 관리자 작성 화면은 승인된 관리자만 접근한다.

## 전자결재 양식 관리

- `/groupware/approval/admin/templates`에서 결재 분류와 양식을 생성·수정·보관한다.
- 양식 필드와 결재 단계별 담당자를 설정하고 저장 시 기존 발행본을 보존한 새 버전을 발행한다.
- 신규 기안은 현재 발행 버전을 사용하고 기존 문서는 작성 당시 양식·결재선 Snapshot을 유지한다.
- 저장 RPC는 승인 관리자 여부, 코드·접두어 형식, 결재선 담당자와 본인 결재 정책을 서버에서 다시 검증한다.
- 사용자는 양식 기본 결재선 대신 승인 직원 이름·부서·직급을 검색해 순차 결재선을 지정할 수 있으며 서버가 본인 결재와 비승인 회원을 차단한다.
- 개인 도장·서명은 비공개 저장소에 등록하고 실제 승인 때 선택한 표시만 이력 Snapshot으로 남긴다.
- 결재 대기 건수는 전자결재 메뉴 원형 배지에, 개인 알림은 상단 알림 패널에 표시한다.
- 활성 최고관리자는 진행 오류나 규정 위반 문서를 사유 입력 후 강제 취소할 수 있고 기안자 알림과 감사 로그가 생성된다.

## G3 시스템 사용량 관리

- 관리자 화면은 회원 상태, 대시보드 구성, 게시판·게시글·댓글·반응, 첨부파일 생명주기와 Storage 용량을 한 번에 집계한다.
- 게시판별 게시글·댓글·본문 이미지·일반 첨부·활성 용량·정리 후보와 게시글 1건 기준 업로드 한도를 표시한다.
- 게시판별 파일·본문 이미지·합산 한도와 원본 보존 여부 변경은 게시판 빌더에서 수행한다.
- 사용량 RPC는 `is_membership_admin()`을 통과한 관리자에게만 집계 결과를 반환하며 사용자명, 이메일, 업로더와 Storage 경로는 반환하지 않는다.
- 업로드 직후 `pending`, 저장 후 `active`, 본문 제거·게시글 삭제·저장 실패 후 `cleanup_candidate` 상태를 구분한다.
- 정리 후보는 최소 24시간의 복구 유예를 두고 표시한다. 관리자 사용량 화면은 파괴적 물리 삭제를 제공하지 않는다.
- DB 메타데이터와 연결되지 않은 Storage 객체는 미등록 객체 수와 용량만 보여 주고, 경로나 소유자 정보는 노출하지 않는다.

## G3 보완: 직원 프로필 관리

- 관리자 화면은 이름·사번·이메일 검색과 부서 필터, 공식 프로필·조직·입사일·재직 상태·회사 연락처 수정, 비공개 사진 확인·교체를 제공한다.
- 역할은 여러 개를 배정·해제할 수 있으나 모든 승인 직원은 `employee`를 유지한다. 관리자 계열 역할의 부여와 해제는 활성 `super_admin`만 가능하다.
- 권장 시작 역할은 보유 역할 중 하나만 선택한다. 현재 활성 역할이 해제되면 서버가 이 값 또는 안전한 남은 역할로 전환한다.
- 본인의 마지막 최고 관리자 제거와 마지막 최고 관리자의 퇴사 처리는 서버에서 차단한다. 위험 역할 변경은 UI 확인과 감사 로그를 함께 요구한다.
- 대시보드 상단 고정 프로필 카드는 숨길 수 없으며 미등록 정보는 빈칸 대신 `미등록`으로 표시한다.
