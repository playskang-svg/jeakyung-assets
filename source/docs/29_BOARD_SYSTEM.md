# 게시판 시스템

## 목적

관리자가 업무 목적에 맞는 게시판을 생성하고 권한·표시 방식을 설정할 수 있는 게시판 빌더의 구현 기준을 정의한다.

## 게시판 설정

- 유형: 일반, 공지, 자료, 익명, Q&A, 갤러리, 프로젝트, 부서, 자유, 사용자 정의
- 테마와 목록 표시 방식
- 카테고리 사용 여부와 정렬
- 댓글·첨부파일·공지·익명 허용 여부
- 표시할 작성자 정보: 이름, 부서, 직급·직책 중 승인된 조합
- 읽기, 쓰기, 관리 권한
- Sidebar 정렬 순서
- 활성, 비활성, 보관 상태

일반 첨부의 기본 단일 업로드 한도는 20MB다. 본문 이미지는 JPEG·PNG·WebP·GIF만 허용하고 SVG는 차단하며, 기본 한도는 장당 10MB·게시글당 20장·일반 첨부와 합산 50MB다. 비공개 `groupware-board-attachments` 버킷과 권한 확인 후 발급하는 짧은 signed URL을 사용하고 실행 파일 계열 확장자는 기본 차단한다.

## 권한 대상

- 게시판 읽기·쓰기·댓글·관리 권한은 역할, 부서, 직급·직책, 특정 사용자 대상으로 설정할 수 있어야 한다.
- 기본은 거부이며 명시적 `allow`가 있어야 허용한다. 같은 사용자가 여러 조건에 해당하면 하나의 `deny`가 모든 `allow`보다 우선한다.
- action은 Sidebar, 목록·상세, 본인·타인 글/댓글, 첨부, 공지·고정, 카테고리·권한·설정·보관·삭제 단위로 분리한다.

## Sidebar 그룹

1. 즐겨찾기
2. 최근 게시판
3. 전사 게시판
4. 부서 게시판
5. 프로젝트 게시판
6. 보관 게시판

- 권한이 없는 게시판은 Sidebar와 검색 결과에 표시하지 않는다.
- 직접 URL 접근도 동일한 서버 권한과 RLS로 거부한다.
- 즐겨찾기와 최근 목록은 접근 권한이 유지되는 항목만 반환한다.

## 콘텐츠 구조

- 게시글: 게시판, 카테고리, 제목, 본문, 작성자, 상태, 공지·익명 여부, 작성·수정 시각.
- 댓글: 게시글, 상위 댓글, 작성자, 본문, 상태와 시각.
- 첨부: 원본명, 저장 경로, 크기, MIME, 업로더와 검사 상태.
- 본문은 Tiptap JSON 문서로 저장한다. 이미지 노드는 장기 URL이나 Base64 대신 `attachmentId`, 대체 텍스트, 캡션, 정렬, 표시 크기만 보존한다.
- 첨부 용도는 `inline_image`와 `general_attachment`로 구분한다. 본문 순서와 이미지 메타데이터는 `board_attachments`에도 동기화한다.
- 익명 글도 서버 감사 기록에서는 실제 작성자를 추적할 수 있어야 하며 일반 사용자에게 노출하지 않는다.

## 본문 이미지 편집

- 검증된 MIT 라이선스의 Tiptap React 편집기를 사용하고 `inlineImage` 커스텀 노드로 교체 가능한 구조를 유지한다.
- 파일 선택·다중 선택·드래그 앤 드롭·클립보드 붙여넣기를 지원하며 업로드 상태와 실패 재시도를 표시한다.
- 이미지는 선택 당시 커서 위치에 삽입하고 대체 텍스트, 캡션, 왼쪽·가운데·오른쪽 정렬, 원본·작게·중간·크게·직접 조절을 지원한다.
- JPEG·PNG·WebP는 브라우저에서 실제 디코딩을 확인하고 긴 변 2560px 초과 시 축소한다. JPEG·WebP는 품질을 조절하며 GIF는 애니메이션 보존을 위해 재인코딩하지 않는다. 관리자는 게시판 설정에서 원본 보존을 선택할 수 있다.
- 외부 HTML 붙여넣기는 위험 태그·이벤트 속성·위험 URL을 제거하고, 서버는 허용된 JSON 노드와 mark만 다시 검증한다.
- 갤러리 게시판은 지정한 본문 이미지 또는 첫 본문 이미지를 대표 썸네일로 사용한다.

## 수명주기

- 삭제는 기본적으로 소프트 삭제한다.
- 게시판 비활성화 후 새 글 작성을 막고 읽기 정책을 유지한다.
- 보관 게시판은 이력을 유지하되 일반 내비게이션에서 분리한다.
- 최종 삭제는 관련 글·댓글·첨부·감사 이력을 확인하고 관리자 서버 함수에서만 검토한다.
- 게시글 저장 전 업로드한 이미지는 `pending`으로 기록하고 24시간 후 고아 정리 후보가 된다. 저장된 본문에서 제거된 이미지는 즉시 영구 삭제하지 않고 `cleanup_candidate`로 전환한다.
- 활성 본문 이미지는 20장을 초과할 수 없다. 이미지 교체 중에는 기존 파일을 먼저 지우지 않도록 Storage에 교체용 임시 1장·최대 10MB 여유만 허용하고, 등록·게시글 저장 함수에서 최종 20장·합산 50MB 제한을 다시 강제한다.

논리 테이블은 [`30_DATABASE_SCHEMA.md`](30_DATABASE_SCHEMA.md), 권한은 [`28_ROLE_AND_PERMISSION_MATRIX.md`](28_ROLE_AND_PERMISSION_MATRIX.md)를 따른다.

## G3 구현 상태

- DB 기반 10종 공통 게시판 엔진과 그룹·카테고리·관리자·권한 규칙을 구현했다.
- 사용자 화면은 즐겨찾기·최근 방문, 게시판 상단의 클릭형 카테고리 탭·검색·페이지 이동, 글 작성·임시저장·수정·소프트 삭제, 댓글·대댓글, 익명, 반응, 첨부 업로드·다운로드를 제공한다.
- 동적 Sidebar와 직접 URL은 같은 DB 권한 함수 결과를 사용하며 비활성·보관·권한 없음 상태를 숨긴다.
- 관리자 빌더는 게시판 생성·수정·복제, 활성·보관·복원, 안전 삭제, 카테고리, 관리자, 세부 allow/deny와 사용자별 권한 미리보기를 제공한다.

## 2026-08-05 운영형 게시판 보완

현재 최우선 작업은 게시판이다. 기존 10종 공통 엔진을 유지하면서 관리자가 실제로 선택해 운영할 핵심 유형을 다음 세 가지로 정리했다.

- 통합게시판: 공지, 자유 글, 자료 공유를 함께 운영하는 기본 목록형
- 갤러리: 본문 대표 이미지를 사용하는 카드형
- 댓글형 게시판: 최근 댓글 활동순으로 대화를 노출하는 토론·문의형

관리자 화면에서는 게시판 종류를 먼저 선택한 뒤 기본 정보와 카테고리를 입력하고, 게시판별로 다음 권한을 역할·부서·직급·직책·특정 사용자에게 부여한다.

- 읽기: Sidebar, 목록, 상세, 첨부 보기·다운로드
- 쓰기: 글 생성, 본인 글 수정·삭제, 첨부 업로드
- 댓글: 댓글 생성, 본인 댓글 수정·삭제

명시적 거부는 허용보다 우선한다. 사용자 Sidebar와 게시판 디렉터리는 `sidebar_view`와 `list_read`를 모두 통과한 게시판만 반환하고, 상세·작성·댓글·첨부는 각 서버 권한을 다시 검사한다. 최고관리자는 사용자별 최종 읽기·쓰기·댓글 권한을 미리 볼 수 있다.

운영 보완 범위:

- 카테고리는 수정 시 ID를 유지하고 제거 항목은 비활성화해 기존 게시글의 분류 연결을 보존한다.
- 글 작성·수정 화면에서 일반 첨부파일을 게시 전에 추가·삭제할 수 있다.
- 기본 정렬은 최신·오래된 글·인기 글을 지원하고 댓글형은 최근 댓글 활동순을 사용한다.
- 목록은 전체 건수와 정확한 전체 페이지 수를 반환한다.
- 작성자 이름과 함께 부서·직급·직책 표시 여부를 게시판별로 설정한다.
- 공지·중요·상단 고정은 게시판 설정과 사용자 권한을 서버에서 모두 통과해야 한다.
- 최고관리자는 게시판 그룹을 생성·수정·활성화·보관할 수 있다.
