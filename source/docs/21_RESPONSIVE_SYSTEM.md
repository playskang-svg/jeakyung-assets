# 반응형 시스템

## 목적

그룹웨어의 화면 폭별 레이아웃, 터치·키보드 접근성과 검수 기준을 정의한다. 공개 사이트 기준은 `WEBSITE_SPEC.md`를 따른다.

## 화면 구간

| 구간 | 너비 | 그룹웨어 기본 동작 |
| --- | --- | --- |
| Small Mobile | 320~389px | 단일 열, 전체 폭 폼, Drawer 내비게이션 |
| Mobile | 390~767px | 단일 열, Drawer 내비게이션 |
| Tablet | 768~1023px | 단일 또는 2열 카드, Drawer 내비게이션 |
| Desktop | 1024~1439px | 고정 Sidebar, Top Bar, 콘텐츠 영역 |
| Wide | 1440px 이상 | 고정 Sidebar와 최대 콘텐츠 폭 유지 |

## App Shell

- Desktop Sidebar 기본 폭은 272px, 접힘 상태는 80px을 기준으로 한다.
- 1023px 이하에서 Sidebar는 화면 밖 Drawer로 전환하고 오버레이를 제공한다.
- Drawer 열기 시 첫 메뉴에 포커스를 이동하고 `Escape`, 닫기 버튼, 오버레이와 메뉴 선택으로 닫는다.
- Drawer가 닫히면 열기 버튼으로 포커스를 복귀한다.
- Top Bar와 Sidebar가 콘텐츠를 가리거나 이중 스크롤을 만들지 않아야 한다.

## 콘텐츠와 폼

- 콘텐츠 최대 폭은 페이지 특성에 따라 1280px 이내로 유지한다.
- 인증 카드는 480px 이내, 내부 콘텐츠 카드는 사용 가능한 폭을 사용한다.
- 입력·버튼의 터치 영역은 최소 44×44px을 유지한다.
- 표가 필요한 향후 화면은 표 자체에 명시적인 가로 스크롤 영역을 제공한다.
- 320px에서 본문 가로 스크롤이 없어야 한다.

## 접근성·모션

- 포커스는 색상 외곽선으로 명확히 표시한다.
- 상태는 색상만으로 전달하지 않고 텍스트와 아이콘을 함께 사용한다.
- `prefers-reduced-motion: reduce`에서는 Drawer와 hover 전환을 즉시 처리한다.
- 200% 확대에서 내비게이션과 핵심 작업을 사용할 수 있어야 한다.

## 필수 검수 폭

- 1440×900, 1024×768, 390×844, 320×720.
- 각 폭에서 인증 폼, 보호 경로 리다이렉트, App Shell 구조, 포커스 순서와 가로 스크롤을 확인한다.
